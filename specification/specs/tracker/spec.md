# Спецификация трекера

## Добавляемые требования

### Требование: управление задачами
Система MUST показывать исходные задачи и MUST позволять добавлять задачи, отмечать их выполненными и удалять. Каждая задача MUST иметь идентификатор, название, числовую оценку в часах и состояние выполнения.

#### Сценарий: исходные задачи
- WHEN приложение открыто в первый раз
- THEN показаны «Чтение» (2 часа, готово), «Практика» (4 часа, активно) и «Повторение» (2 часа, активно)

#### Сценарий: добавление задачи
- WHEN пользователь отправляет корректное название и количество часов
- THEN новая активная задача появляется в списке, форма очищается

#### Сценарий: изменение статуса
- WHEN пользователь переключает отметку задачи
- THEN статус этой задачи меняется, сводные показатели пересчитываются

#### Сценарий: удаление задачи
- WHEN пользователь нажимает кнопку удаления задачи
- THEN задача удаляется, сводные показатели пересчитываются

### Требование: валидация ввода
Система MUST обрезать пробелы по краям названия и отклонять пустые названия. Количество часов MUST быть конечным числом от 0,5 до 24 включительно с шагом 0,5. Пустое поле часов MUST NOT трактоваться как ноль. Некорректная отправка MUST NOT добавлять задачу; понятная ошибка MUST отображаться рядом с соответствующим полем, а введённые значения MUST сохраняться для исправления.

#### Сценарий: пустое название или пробелы
- WHEN название пустое или содержит только пробелы
- THEN задача не добавляется и показывается ошибка названия

#### Сценарий: некорректное количество часов
- WHEN часы не указаны, не являются конечным числом, меньше 0,5, больше 24 или не кратны 0,5
- THEN задача не добавляется и показывается ошибка часов

#### Сценарий: граничные значения
- WHEN пользователь указывает 0,5 или 24 часа
- THEN значение принимается

### Требование: прогресс по часам
Система MUST рассчитывать суммарные часы как сумму часов всех задач, а выполненные часы — как сумму часов выполненных задач. Прогресс MUST рассчитываться по формуле `round(100 * completedHours / totalHours)`. Если суммарные часы равны нулю, прогресс MUST составлять 0%, без NaN или Infinity.

#### Сценарий: исходный прогресс
- WHEN отображаются исходные задачи
- THEN всего 8 часов, выполнено 2 часа, прогресс 25%

#### Сценарий: практика выполнена
- WHEN задача «Практика» (4 часа) отмечена выполненной
- THEN выполнено 6 из 8 часов, прогресс 75%

#### Сценарий: пустой список
- WHEN все задачи удалены
- THEN всего 0 часов, выполнено 0 часов и прогресс 0%

### Требование: фильтрация
Система MUST предоставлять фильтры «Все», «Активные» и «Готовые». Фильтр MUST менять только видимость задач; сводные показатели MUST рассчитываться по всем задачам, в том числе скрытым.

#### Сценарий: фильтр активных задач
- WHEN на исходном наборе выбран фильтр «Активные»
- THEN видны «Практика» и «Повторение», а прогресс остаётся 25%

### Требование: адаптивный и доступный интерфейс
Система MUST оставаться читаемой при ширине 390 CSS-пикселей без горизонтального переполнения. Поля и действия MUST иметь видимые подписи или доступные имена, ошибки валидации MUST быть связаны с соответствующими полями.

#### Сценарий: узкий экран
- WHEN ширина окна равна 390 CSS-пикселям
- THEN горизонтальная прокрутка отсутствует, все элементы управления остаются доступными
